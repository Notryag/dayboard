# Agent 评估规范

状态：当前规范（规范版本）  
最后验证：2026-08-23

## 评估层级

| 层级 | 用途 | 权威来源 | 正常执行 |
| --- | --- | --- | --- |
| 确定性 CI | 证明 schema、策略、持久化、隔离、Run 生命周期和投影正确。 | 代码、PostgreSQL、类型化事件。 | 受影响规范的必需检查。 |
| Agent 验收 | 使用小型目录对已部署的 HTTP 到模型再到工具路径进行冒烟测试。 | 终态 Run、工具调用、持久化产品状态。 | 明确的发布/部署门禁。 |
| Agent Eval | 在版本化的中文调度语料上衡量行为。 | 精确工具、终态、PostgreSQL 支持的 REST Oracle、安全断言。 | 明确的模型/发布门禁。 |

这些层级相互补充。实时模型通过不能替代确定性正确性，确定性 CI 也不能证明模型分类质量。

## Oracle 规则

- 产品写入以普通的用户范围 PostgreSQL API 为准，绝不以助手文本或模型回执为准。
- 当顺序或重复调用会影响正确性时，工具预期使用精确调用次数和禁用工具断言。
- 澄清用例验证持久化选择、状态版本、选定身份、延续 Run、最终产品状态以及一次性交互的消费。
- 相对日期模板在每次 Eval 执行时只捕获一次，避免 Run 跨越午夜而漂移。
- 未知的 provider 缓存详情仍保持未知，绝不报告为零。
- Token 预算需要可复现的已部署基线，并预留方差余量。

## 证据与回归策略

每个 Run 都记录稳定的 request、Thread、Run 和工具调用身份，以便在 HTTP、排队、模型调用、工具、持久化事件和产品状态之间追踪失败。报告是构建或外部工件，而不是提交进仓库的生产历史。

暴露可复用行为缺口的生产故障，应转化为最小的适当回归资产：断言由宿主负责时优先使用确定性测试，否则使用版本化 Eval 用例。主观文本评分不得替代精确的工具、状态、schema 或数据库断言。

## 发布门禁

安全、分类、修改和取消类别即使总体准确率达标，也必须满足各自配置的类别阈值。完整实时模型执行仍需明确触发，因为它会写入数据、产生 provider 成本，并依赖 provider 可用性。

操作命令和语料详情见 [Agent Eval 指南](../../guides/agent-eval.md)。较小的已部署冒烟目录见
[Agent 验收指南](../../guides/agent-acceptance.md)。语料结构和指标计算由
[`test_agent_eval.py`](../../../apps/api/tests/test_agent_eval.py) 保护。
